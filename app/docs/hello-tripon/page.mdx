# Hello, Tripon

Every language has a program that proves the compiler works end to end. This is
Tripon's — `examples/hello.tp`, a file the test suite runs on every commit:

```tripon
// examples/hello.tp - the canonical smoke test
// run: ralt run examples/hello.tp

use tier core;

extern "C" {
    fn puts(p: str) -> i32;
}

fn main() -> i32 {
    puts("hello from tripon");
    return 0;
}
```

## Line by line

**`// …`** is a comment to the end of the line. `/* … */` is a block comment. There
is no preprocessor and nothing is stripped before the code is read, so a comment
can never change what the program means.

**`use tier core;`** declares the tier ceiling for this file. Tiers run from `kernel`
(no allocator, no runtime — firmware) to `full`, and the declaration is what tells
the compiler which features the file may reach for. A file that declares nothing
defaults to `core`. [The tier system](/docs/language/tiers) has the full table.

**`extern "C" { … }`** is a fenced island. Functions declared inside it are raw C
symbols taking raw pointers, and the fence is the only place a pointer type may
appear: everything outside it is pointer-free and memory-safe. Here `puts` is
declared as taking a `str` and returning `i32`, which is exactly how it is called.

**`fn main() -> i32`** is the entry point. The return type is not decoration — it
becomes the process exit status, which is why `main` returns `0` at the end. A
file with no `main` is `E0501`; a function that returns nothing is written `-> ()`.

**`puts("hello from tripon");`** passes a string literal. A `str` is a UTF-8 slice;
the literal lives in the binary's read-only data, so this call allocates nothing.
Semicolons are mandatory, as are braces around every block. Nothing in Tripon is
optional in a way that could be read two ways.

**`return 0;`** — early returns are ordinary, and every path through `main` must
return a value.

## Locals infer, signatures do not

Parameters and return types are always written out. Locals are the one place the
compiler infers, and it infers from the initializer:

```tripon
fn fib(n: i32) -> i32 {
    let a = 0;          // i32: the default integer type
    let b = 1;
    let idx = 0;
    while idx < n {
        let next = a + b;
        a = b;
        b = next;
        idx += 1;       // compound assign; there is no ++
    }
    return a;
}
```

`let` is reassignable and `const` is not — reassigning a `const` is `E0203`, not a
warning. There is no `var`, no `for`, and no truthiness: a condition is a `bool`, and
an integer in an `if` is a type error rather than a convention.

## Exit status

`main` returns a status, and `ralt run` propagates it. There are four statuses worth
branching on:

| status | meaning |
|---|---|
| `0` | clean, or warnings only |
| `1` | at least one diagnostic with severity `error` |
| `101` | the program trapped at runtime |
| `2` | the command line itself was wrong |

The last one is the interesting one: `101` is a trap, which is how a division by
zero reports itself. It is defined behaviour, it names its code and its line, and it
is not a crash — see [traps](/docs/language/traps).
